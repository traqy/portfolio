Selected AI & Agentic Initiatives

“Agentic-Ready Baseline” — org-wide AI platform program (Author & Owner, as Head of Engineering)

Defined and led a company-wide initiative to modernise six data/AI services into a standard, agentic-ready baseline — each operable by humans via dashboard and by AI agents via API. Authored the architecture: service-independent control-plane APIs for agent consumption, MCP-compatible tool manifests for agent tool discovery, Google + GitHub SSO, scoped/hashed API keys, per-service OpenTelemetry observability with SLOs, SSM secret management (zero .env secrets, gitleaks-verified), and a Python 3.12 / FastAPI / GitHub Actions baseline. Established a pluggable auth + observability “seam” pattern so services ship foundation work immediately and integrate shared infra with zero handler churn.

despicable — multi-agent Slack bot fleet

Architected a fleet of role-based AI agents (e.g. a read-only data-analyst persona) that operate internal services through their control-plane APIs — the primary agentic consumer of the platform above. Handled live-credential security (AES-256-GCM at rest), per-role scoping, and agent-to-service smoke tests as the definition of done for “an agent can operate this service.”

owl-analytics — agent-operated analytics service

Designed a standalone, security-hardened analytics service that productizes the agent's data-analyst capability: read-only warehouse access with a strict SQL safety guard (bound parameters only, allowlisted identifiers), deny-by-default RBAC, fail-closed auth, KMS-encrypted artifacts with short-lived signed URLs, append-only audit, PII-free telemetry, and an MCP manifest so agents discover analyses as callable tools.

Modernised the AI/data service estate

Set the architecture patterns and led modernisation across the internal AI/data services — a competitive-landscape visualisation tool (also the platform's visual + API-key reference exemplar), a large-scale web-scraping pipeline (Scrapy/ScrapyD → S3), an AI article-generation service, a retrieval-augmented (RAG) editorial assistant, and an article-recommendation engine.

daily-toast-system — AI-assisted engineering methodology

Codified a prompt-driven SDLC adopted across the team: PRD + Figma (MCP code-connect) → structured “AI Context Documents” (ARCHITECTURE + JTBD checklists) → LLM code generation → senior human review/integration → peer-reviewed PR. Delivered as a multi-repo product (PayloadCMS, n8n automation, Next.js).

mimiq — multi-agent engineering-org simulator (personal project · github.com/traqy/mimiq)

Built a system where a fleet of specialist AI agents (PM, full-stack engineer, QA, designer) collaborate in real time and write actual, git-committed code to disk. Engineered the hard parts of agent autonomy: a Redis Streams event bus draining to MongoDB history; supervisor-orchestrated api/bridge/runner processes; an independent Overseer that monitors for behavioral violations; five layers of guardrails (per-agent stream cursors, human-checkpoint pauses, @mention routing, stage-skills enforcement, rate limiting); sandboxed Docker execution of agent-built apps; OAuth/RBAC; and live token/cost tracking.
